# スティック押し込みの解析（2026-10-16）

## 結論

押し込みは再割り当て可能。実機でF19への変更と入力を確認した。
元ソフトの画面には選択領域がないが、保存される20列×8行のキー行列には含まれる。
Web UIにはまだ追加していない。

| 項目 | 値 |
| --- | --- |
| 行列位置 | row=0、column=16（0始まり） |
| 設定内オフセット | `0x48 + 16*8 = 0xC8` |
| 今回の設定ベース | `0xE0` |
| EEPROM絶対アドレス | `0x1A8` |
| 保存サイズ | 1バイト。他の行列キーと同じ列優先形式 |
| 初期値 | `0xF4` = メーカー独自の `KBD Mode` |
| 検証値 | `0x6E` = Keyboard F19 |

`0xF4` は通常のF4キーのHID Usageではない。F4キーは `0x3D`。
隣のcolumn=17は初期値 `0xE9` だが、今回その物理操作は同定していない。

## 元ソフトの根拠

対象 `Gaming Keyboard.exe` のSHA256:
`ef79b5e0ad1786dd682bc8ed1dad4626627c0518639ec67a702088d6322b8e36`。
旧配布版から展開済みの実行ファイルも同一ハッシュだった。
実行ファイルはWindows上で起動せず、既知範囲のUnicornエミュレーションで検証した。

- `config/KBconfig.ini` の `[KBconfig]` は `0_16=244`、`0_17=233`。
- `1/skins/1_INI_EN/KB.ini` の有効な選択領域は18個。
  12キー、スティック4方向、ホイール2方向で、押し込みの領域はない。
  `Fn` 等のコメント行を有効な操作と数えてはいけない。
- `0x40A7C1..0x40A808` はUTF-16文字列 `KBD Mode` を比較し、`ESI=0xF4` とする。
- `0x411021..0x411134` のシリアライザは、非表示列も含めて20列の各8バイトを書き出す。
  メモリ内row-majorの値をEEPROMのcolumn-majorへ変換する。
- このため「元ソフトのGUIから選択できない」と「本体が再割り当てを受け付けない」は別。

再現用（USBアクセスなし）:

```powershell
uv run --group research python tools/verify_stick_press.py "research/official/app/Gaming Keyboard.exe" research/official/app/1/skins/1_INI_EN
```

## 実機検証

1. 設定248バイトを読み取り、検証直前の状態をバックアップした。
   先頭バイトは `0x40`、押し込み候補は `0xF4` だった。
2. `config+0xC8` のみ `0x6E` へ変更した。先頭8バイトの再送と通常の設定終了処理を実施。
   隣接7バイトを維持し、設定全体を読み戻して一致を確認した。
3. ユーザーが中央を2回押し、左上キーを1回押した。
   K810だけを対象とするWindows Raw InputでF19の押下・解放1組とCtrl+F13を取得した。
   続く読み取りで先頭バイトが `0xC0` へ変化していた。
4. さらに「中央1回→左上1回」を3組実施。
   **F19の押下・解放3組とCtrl+F13の3組**を取得した。
   F19のVKは130（`0x82`）、scanは106（`0x6A`）。押下flags=0、解放flags=1。
5. 今回変更した押し込み値と変化した先頭ビットを検証直前へ復元し、248バイト全体の一致を確認した。
   過去の別の実験用割り当てまで工場設定へ戻した、という意味ではない。

### モードの制約と未検証事項

先頭バイトのbit7が0の状態では、最初の押し込みが既定操作からカスタム側へ切り替える動作と整合する。
bit7が1になった後は、3回とも割り当てたF19が出ており、押すたびにモードが切り替わる挙動ではなかった。
したがって、通常キーとしての利用はカスタム側のモードで検証済み、と区別する。
ファームウェアを抽出して内部の分岐を証明したものではない。

元の `KBD Mode` を上書きすると、そのモード切替操作を失う可能性がある。
今後UIへ追加する際は、元の値を復元する経路とモード状態を考慮する必要がある。
任意のメディア操作、マクロ番号、USB再接続後の動作については、押し込みではまだ実機検証していない。
保存位置が共通であることだけから、これら全ての動作保証とはしない。

`tools/probe_stick_press.py` はこの調査の一時変更・復元用。
通常CLIの対応機能には含めず、未同定のcolumn=17を押し込みとして公開しない。
