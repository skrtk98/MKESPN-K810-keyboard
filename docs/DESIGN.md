## 情報構成

- 大きい画面は公式水平メニュー、小さい画面はハンバーガーボタンとメニューリスト。
- 区分は「キー・ホイール」「Light」「マクロ」「バックアップ」「使い方」。リンクと `aria-current` で現在地を表す。ARIAのタブ部品ではない。
- 接続状態はヘッダー、保存操作は設定領域の後、非公式表記・出典はページ末尾に置く。
- 設定を変更しても、自動で本体へ保存しない。下書き追加と本体保存は区別する。

## 公式部品と独自部品

導入元は [NOTICE](../web/vendor/dads/NOTICE.md)。CSSは無改変で使用する。

| 部品 | 使用方針 |
| --- | --- |
| button | 本体保存はsolid-fill、編集補助はoutline/text |
| select | 静的・動的の両方でcontrol・select・chevronを揃える |
| input-text | 数値・テキストの48px入力、通常・無効・エラー状態を使用 |
| checkbox | 公式sm構造。24pxの外側領域とラベルを使用 |
| form-control-label | 関連ラベルと入力の構造・余白を統一 |
| accordion | 使い方の同種の説明を並べる |
| disclosure | 単独補足と変更一覧に使用 |
| notification-banner | 通常フローの通知領域。編集欄に重ねない |
| modal-dialog | 通信・保存・読み込み等の操作全体が失敗したときに使用 |

キーボードの配置図、RGB色入力、操作行の編集、画面全体の配置は独自部品。外部フォント、外部スクリプト、アクセス解析は追加しない。
`form-controls.mjs` が入力部品の構造と欄内エラーを共通化する。

## 各編集画面

キー割り当ては「操作の種類」と「キー・操作」の2段階。幅は最大16rem。カテゴリだけを変更しても下書きを変更しない。既存マクロや未知コードは保持する。
小さい画面では図・キー設定・ホイールを切り替える。静的サイトに入力監視・入力テスト・入力ハイライトは設けない。

821px以上は図を左列、選択したキーとホイールを右列の上下に配置し、図は右側の2区分にまたがる。操作カテゴリとキーの選択欄も横に並べ、各欄は最大16remを保つ。
「本体の設定」とキー単独の「元に戻す」は未保存の変更がある場合だけ表示し、通常時は選択欄と同じ値を繰り返さない。

図のキー表記は実機の印字（1〜8、9、0、TAB、ENTER）で固定する。現在の割り当ては各キーのtitleツールチップと読み上げ名に含め、未保存の場合は本体の値と変更後を区別する。
印字6の幅は通常キーの1.5倍、TABは1.75倍。ENTERは上部が広く下部左側に段差がある形状と縦の印字で描く。これらは表示だけの変更で、キー位置と設定アドレスの対応は変更しない。

スティックはキー群の右上の円形4方向、ホイールはその下の縦長の形状として描く。印字は矢印で固定し、方向ごとの割り当てをtitleと読み上げ名に含める。ホイールの上半分・下半分から対応する方向の編集欄へ移動できる。スティック中央は装飾であり、押し込みの割り当て操作は提供しない。

Lightは基本設定、動き・反応、パレットを選んで表示する。表示切り替えで入力値を破棄しない。変更への追加は全項目をまとめて行う。
点灯モード名は元ソフトの英語名を保つ。基本設定の明るさと速度は狭い画面でも横に並べ、パレットは折り返す。

マクロはショートカット、マウス操作、操作の組み合わせ、入力から記録、ライブラリのうち1つを表示する。
操作の組み合わせは選んだ操作行だけを編集する。全行のデータは保持し、行番号は操作行の選択欄・読み上げ名で伝える。追加・削除・並べ替えを提供する。
照明シーケンスも選んだ段階だけを編集する。ライブラリはマクロ・グループ・ファイル入出力を切り替える。
記録は明示的に開始した欄内だけが対象で、終了後は操作の組み合わせへ移る。

## 文字・余白・状態

本文とフォームの文字は16pxを基本とする。配置図の補助表示、変更件数・一覧、フッターは14px。画面に収めるため文字を縮めない。
色は公式トークンを使い、フォーカスには公式の黒・黄色を保持する。番号を全見出しに付ける規則は設けない。
未接続・通信中・状態不明時の本体保存は無効化する。入力の通常・無効・ホバー・フォーカス・エラー状態は公式CSSを使う。

入力値の誤りは該当欄の近くへ理由を表示し、`aria-invalid` と `aria-describedby` を設定する。入力を修正すると解除する。
数値入力は空欄・範囲・刻みを検証する。編集中の行に不正な値がある場合は、修正するまで別の操作行へ移動しない。
通信・保存など全体の失敗は1つのモーダルで伝える。同じ内容のバナーを同時には残さない。確認・閉じる・Escapeで閉じられる。
成功・情報・警告は通常フローの公式バナーで伝える。警告は三角形と感嘆符、情報は円とi、成功は円とチェックで区別する。通知を自動消去しない。
通知・ダイアログ・エラー文にはtextContentを使用し、入力された文字をHTMLとして挿入しない。

## レスポンシブとスクロール

十分な高さがある場合はヘッダー・保存操作・フッターを含む画面を構成する。設定が収まらない場合はResizeObserverで通常のページスクロールへ切り替える。
低い画面（680px以下）と非常に狭い画面（360px以下）もページスクロールを使い、固定領域で編集欄を押し潰さない。
接続ボタン列は折り返し可能にする。ラベル・補足・長いエラーが横にはみ出さないようにする。
長いマクロでも全行を縦に積み上げない。任意の小画面・長文でスクロールが一切生じないことは目標としない。
